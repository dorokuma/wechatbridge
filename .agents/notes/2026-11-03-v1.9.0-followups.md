# v1.9.0 UX 批次 — 遗留 follow-ups

来源：oracle/reviewer 第 1 轮审查观察项（不阻断，登记跟踪）。

## O1 `_sanitize_display_filename` 未过滤零宽/双向控制字符

- **来源**：oracle
- **位置**：`wechatbridge/main.py:75-85`
- **风险**：未过滤零宽字符 U+200B–U+200F、双向控制符 U+202A–U+202E /
  U+2066–U+2069、U+FEFF、全角＠ U+FF20。仅视觉欺骗（显示文件名可含隐形
  或方向反转字符），无 `@path` 注入风险——落盘文件名仍走
  `uuid.hex[:12]+ext` 安全路径。
- **建议**：加入黑名单并在注释固化「剥离一切 @ 等价物」契约。

## O2 快照/回退扫描超限时产物静默丢弃

- **来源**：oracle
- **位置**：`runner_common._snapshot_regular_files` /
  `collect_session_fallback_artifacts`
- **风险**：超过 200 文件 / 50 目录 / 2 秒上限时返回空集，本轮产物被
  静默丢弃，用户只看到文字回复、没有任何提示。
- **建议**：给用户一句提示或至少记 warning 日志。

## O3 共享 `config.agy_scratch_dir` 作为 agy 链接白名单根

- **来源**：oracle
- **位置**：`agy.py run_agy` 的 `extract_artifacts` allowed_roots
- **风险**：跨用户引用依赖命名/mtime 隔离；属 v1.8.0 已接受残余风险，
  本轮未变。
- **建议**：维持现状；若未来收紧，可考虑按用户隔离 scratch 子目录。

## O4 `extract_artifacts` 放行与发送层拒绝不一致

- **来源**：oracle
- **位置**：`extract_artifacts`（normpath 放行）vs `send_artifacts_back`
  （realpath 拒绝）
- **风险**：session 内 symlink 指向外部文件时，extract 层放行、发送层
  realpath 拒绝，产生「不在允许回传目录内」噪音提示，可能被刷屏。
- **建议**：extract 层也改用 realpath 校验，前后一致。

## O5 relogin 排空对 `slot.held` 的依赖

- **来源**：oracle
- **位置**：main.py relogin 排空路径
- **风险**：实现正确但依赖标志语义，较脆弱（重构时易破坏隐含契约）。
- **建议**：加注释/测试固化该语义。
