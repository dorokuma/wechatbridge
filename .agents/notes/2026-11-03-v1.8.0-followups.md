# v1.8.0 安全修复 — 遗留 follow-ups

来源：reviewer 第 2 轮审查（r2）consider 项，提交门禁已通过，以下为不阻断的观察项记录。

## 1. update.sh `check_access_control_env` grep 正则与空引号值

`deploy/update.sh` 的 `check_access_control_env` 中 grep 正则把
`WECHATBRIDGE_ALLOWED_SENDERS=""` / `''` 当成非空有效配置，但
`wechatbridge/config.py:_parse_env_file` 会 strip 引号解析为空串并触发
fail-closed。

**影响**：仅升级脚本警告提示精度，不影响桥进程鉴权本身。

## 2. `_matches_session_secret_content` 宿主凭据清单未含 agy token

宿主凭据清单含 dsh `.credentials.yaml`、`~/.grok/auth.json`、
`~/.codex/auth.json`，但未含宿主
`~/.gemini/antigravity-cli/antigravity-oauth-token`（`agy.py:95`）。

**影响**：仅在跨后端且 agy 会话目录从未初始化（或 `sess_real=""`）时，宿主
agy token 不会命中内容比对；默认 agy 会话因 `ensure_user_gemini` 同步不受影响。

## 3. update.sh 本地路径安装源刷新策略（第 1 轮返修处置）

来源：C 档审查（fix/update-local-src，reviewer 第 1 轮）consider/观察项，
本轮返修已按以下结论处置：

- **远程 VCS/归档 URL 安装源**（如 `git+https://...` 或固定 `.whl` URL）：
  `deploy/update.sh` 仅对本地路径（`/*`、`file://*`）执行
  `git -C <dir> pull --ff-only`，其余非本地 spec 统一交由
  `pipx upgrade wechatbridge-cli` 处理。这样避免 `pipx reinstall` 清空
  `runpip` 安装的依赖（如 `PyYAML`）或破坏 pinned 状态。
- **`--python python3` 已移除**：升级路径不再传 `--python`，交由
  `pipx upgrade` 沿用 venv 内原 Python 解释器，保留原有 pinned 语义。
- **`pipx_package_or_url` 备用路径改为直接读取 `pipx_metadata.json`**：
  不再解析 `pipx list` 文本输出，消除 pipefail/SIGPIPE 风险与假文本解析；
  候选路径依次为 `$PIPX_HOME/venvs/...`、目标用户
  `~/.local/share/pipx/venvs/...`、`~/.local/pipx/venvs/...`。
- 本地路径刷新失败（目录不存在、非 git 仓库、`git pull --ff-only` 非 0）时
  立即 `exit 1` 并打印 `ERROR:`，绝不静默假升级。
